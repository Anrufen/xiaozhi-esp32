# 05 — 可分发构建：个人覆盖文件 + 镜像凭据扫描

**What to build:** 我有两种构建：自用构建带我的个人默认值，分发构建不含任何个人信息。分发构建出来后有一个自动检查，能证明固件镜像里没有我的凭据；自用设备从旧固件升级后行为不变。

**Blocked by:** 01 — 配置模块 + Navidrome 端到端可配置；02 — Beszel 端到端可配置；03 — 未配置状态；04 — 服务功能编译开关

**Status:** ready-for-agent

- [ ] 个人默认值放在不入库的本地覆盖文件里，通过构建参数叠加到默认配置；不得编辑任何 `sdkconfig*`、`build/`、`releases/`
- [ ] 本地覆盖文件的路径和示例模板（只含占位值）写入文档；仓库中不得出现任何真实地址、账号、密码
- [ ] 提供凭据扫描步骤：对生成的合并固件镜像做字符串扫描，命中使用者本地提供的"禁用字符串列表"即以非零状态失败；该列表文件不入库
- [ ] 扫描步骤有自动化测试，覆盖"命中失败"和"未命中通过"两种情况，纳入 `python3 -m unittest discover -s scripts/tests -v`
- [ ] 用空覆盖文件构建一个分发包，扫描通过；用带个人默认值的构建，扫描应能检出（用于证明扫描有效）
- [ ] 自用构建烧录到已有设备（保留 NVS，仅写 APP 分区）后，Navidrome 与 Beszel 无需重新配置即可工作
- [ ] 现有 `dist/` 中旧发布包被标注为含个人凭据、不可分发（或被清理），并在最终报告中说明
- [ ] 最终报告明确列出：已验证的内容，以及仍需真机验证的内容
